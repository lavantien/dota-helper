# picker generated data contract

`picker/picker-data-generated.js` is written by `make emit` (engine `emit picker`). do not edit by hand. shape:

```js
window.PICKER_GEN = {
  date: '2026-09-24',          // run date
  patch: '7.41f',
  rosterCount: 127,            // derived from roster table, never hardcoded
  slugs:  [...],               // parallel arrays in hero_id ascending order
  names:  [...],
  icons:  [...],               // short npc names (prefix stripped) for the CDN icon url
  pop:    [...],               // 127 popularity values in [0,1]
  aliases: { 'furion': 'natures-prophet', ... },  // config.aliases, alias slug -> canonical roster
                               // slug, search/display only, never scores; emitter drops pairs whose
                               // value is not a roster slug or whose key shadows one
  poolIdx: [...],              // roster indices of pool heroes, in slug-ascending pool order
  entries: [                   // parallel to poolIdx
    { roles: ['2','3'], tier: { '2': 'dedicated', '3': 'flex' } }
  ],
  prose: [                     // parallel to poolIdx, the why/how/when framework
    { identity: '...', why: '...', how: '...', when: '...',   // from content.json,
      build: '...', timings: [['midas', 12]], tech: ['...'],  // same source as the guide
      mechanics: [['tip'|'counter', '...']] }                 // grounded in howdoiplay
  ],
                               // prose methodology: identity/why/how/when/tech are first-principles
                               // kit prose, no numerals beyond pos/level facts, numbers live in the
                               // data arrays. build/timings are stratz-derived, synced into
                               // content.json by make sync-builds (multi-role heroes carry per-role
                               // segments). mechanics are howdoiplay-grounded lines verified against
                               // current-patch sources, provenance in ref/dota2/howdoiplay/curated.json
  mu:  [...],                  // parallel to poolIdx: 'idx:pct:conf,idx:pct:conf,...'
  syn: [...],                  //   idx = enemy/ally roster index, pct in [0,1] at 4dp,
                               //   conf 0 = high, 1 = medium, 2 = low
  prior: [...],                // parallel to poolIdx, midrank percentile of the pure overall-winrate
                               // z-score, no tier term. tier is a board label only (dedicated by
                               // default, flex only when explicitly authored): it renders the flex
                               // chip and never scores
  heroPos: [                   // parallel to poolIdx, display only (never scores): per hero the
    [[1, 0.6, 0.5333], ...]    // farm positions as [position, share of the hero's own picks, wr]
  ],                           // share-descending, empty array when no position data crawled yet
  trend: [                     // parallel to poolIdx, display only (never scores): per hero the
    [0.8, -0.3] | null         // latest-pair movement [wr delta pp, pick share delta pp] between
  ],                           // the two most recent snapshot dates, null before two snapshots
  roles: [{ id, label }, ...], // role definitions from the config hub
  weights: { knownMu, synByRole: {role: w}, prior, genericFit, exposure, flexibility },  // synByRole
                               // weights the knownSyn phase by the role being picked (authored:
                               // supports pair with the picked allies at full weight, cores less)
  scoreConsts: { enemySlots, allySlots, midPct, flexCap, flexHalf },  // from config.score,
                               // the JS twin reads them here instead of hardcoding
  meta: {
    bracket: 'DIVINE_IMMORTAL',
    window: 'stratz 7-day window, pairs on the last completed week, not patch pure',
                               // derived from stratz.take by the emit, never a frozen literal:
                               // winDay surfaces (popularity, positions, trends) roll the take
                               // window, the pair and item tables pin the last completed week
    perHeroSource: { '<slug>': 'stratz' | 'opendota_explorer' }
  },
  gates: { roleNotes, fallbackOrder, rules, autogenerated, gateDeltas, aoeClearHeroes }
                               // fallbackOrder arrays are per-position win-rate sorted in divine-immortal
                               // ranked all pick, rewritten by `make order-pool` (display order only,
                               // never scores, membership owned by config.json)
};
```

mu rows are full and unfiltered: every roster hero appears once per pool hero, pct is the within-hero midrank percentile after shrinkage, normalization, and completion. higher pct = better for the pool hero (matchup pct inverts dis sign, synergy pct keeps the synergy sign). Go fixtures and picker-score.js must read the same 4dp-rounded values so rankings agree to 1e-6, tie-break hero_id ascending.
